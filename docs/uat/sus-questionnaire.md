# System Usability Scale (SUS)

Standard instrument (Brooke, 1986), reproduced verbatim — do not reword the items, that breaks the standardized scoring. Administer after the 4-week independent-use period.

For each statement, mark one: **Strongly disagree (1) — Disagree (2) — Neutral (3) — Agree (4) — Strongly agree (5)**

1. I think that I would like to use DoSmart frequently.
2. I found DoSmart unnecessarily complex.
3. I thought DoSmart was easy to use.
4. I think that I would need the support of a technical person to be able to use DoSmart.
5. I found the various functions in DoSmart were well integrated.
6. I thought there was too much inconsistency in DoSmart.
7. I would imagine that most people would learn to use DoSmart very quickly.
8. I found DoSmart very cumbersome to use.
9. I felt very confident using DoSmart.
10. I needed to learn a lot of things before I could get going with DoSmart.

*(Only the product name was substituted into the original wording; substituting a name in for "the system" is the standard, accepted adaptation.)*

## Scoring

For each participant:

- Odd items (1, 3, 5, 7, 9): `score = response − 1`
- Even items (2, 4, 6, 8, 10): `score = 5 − response`
- Sum the 10 item scores (range 0-40), multiply by 2.5 → SUS score out of 100.

Report the **mean SUS score across all participants**. This project's target (from the spec) is ≥85/100, which Bangor et al.'s norms place at "excellent"/"best imaginable" — a high bar, so treat it as a stretch target, not a pass/fail gate on its own; pair it with the qualitative debrief notes from `test-script.md` and the TAM results.
